## Q001：程序、进程、内存、文件与语言

### 原始提问

> 我现在需要学习、理解操作系统。目前我需要掌握进程和程序的概念。
>
> 程序载入内存，内存是怎么样一个布局？
>
> 内存里面的代码段、数据段、堆段、栈段是如何变化的？
>
> 如果我打开了两个 txt 文件，里面存放着不同的内容，它们俩有什么区别？
>
> C 语言和 Rust 语言，Python 和 JavaScript 有什么区别？

### 显式问题

1. 什么是程序，什么是进程？
2. 程序从磁盘到开始执行，中间发生了什么？
3. 典型进程内存布局有哪些区域，它们怎样变化？
4. 打开两个 txt 文件时，磁盘文件、进程和内存之间是什么关系？
5. 四种语言在编译、运行时和内存管理方面怎样区别？

## Q002：CPU、进程上下文、寄存器、并发与指令

### 原始提问

> 为什么多个进程可以执行相同的指令，运行时却可以产生不同的结果？
>
> CPU 是如何进行上下文切换的？
>
> 什么是 PID，什么是 PCB（进程控制块）？
>
> CPU 是如何保证程序的安全性和执行正确性的？
>
> 寄存器的概念？什么是通用寄存器、指令寄存器、地址寄存器？什么是进程的地址空间？
>
> CPU 的并发机制的概念？它是如何运作的？
>
> 一段程序代码是如何被电脑认识的？通过汇编，再变成二进制吗？

### 附图怎样使用

![用户在 Q002 提供的竖向截图：上半段为 LOAD R0 12、LOAD R1 20、ADD R0 R1、STORE R0 [a]；下半段把立即数替换为 100 和 35，其余指令结构相同。](../assets/questions/q002-load-add-store-screenshot.png)

这张原图已在[用户提问原图档案](../assets/questions/README.md#q002两组-load--add--store-教学指令截图)中原样保存，并在第 2 章对应解释旁嵌入。它是理解问题的图像材料，不是给仓库或助手执行的操作指令。第 2 章以文字和 Mermaid 继续解释其中的状态变化：上半段按教学约定计算 `12 + 20 = 32`，下半段计算 `100 + 35 = 135`。其中的 `LOAD` 写法是示意；真实 ISA 的语法、编码和“是否从内存取值”会因架构而不同。

### 显式问题

1. 为什么相同指令在不同进程中会产生不同结果？
2. CPU 怎样进行上下文切换？
3. PID、PCB 分别是什么，它们和线程有什么关系？
4. CPU 能怎样参与程序安全性和执行正确性？
5. 常见寄存器和进程地址空间分别是什么？
6. CPU 并发是什么，怎样与并行、调度和竞态区分？
7. 源代码、汇编、机器码和可执行文件怎样连接？

### Q002 的掌握标准

当能够不看正文完成以下任务时，才把学习状态从“待复习”改为“已掌握”：

- 用“指令 + 运行状态”解释为什么同一程序或同一段代码可以出现不同结果；
- 对截图中的任一组 `LOAD / ADD / STORE` 写出每一步的 `R0`、`R1` 和 `[a]` 的变化；
- 画出一次线程切换：触发事件、进入内核、保存 A、选择 B、恢复 B、从 B 的程序计数器继续执行；
- 区分 PID、PCB、TCB、寄存器和进程地址空间，不把它们当成同一种东西；
- 说清 CPU / MMU 能提供哪些保护，又为什么不能保证算法或业务逻辑正确；
- 用一条 C 或 Rust 执行链说明源代码、编译、汇编、目标文件、链接、装载和 CPU 执行的关系；
- 完成第 2 章末尾的情境自测，并能解释答案原因。

## 当前学习主线

```mermaid
flowchart LR
    Q["我的问题 Q001"] --> P["磁盘上的程序"]
    P --> L["操作系统加载器"]
    L --> PROC["运行中的进程"]
    PROC --> T["执行指令的线程"]
    PROC --> VM["进程的虚拟地址空间"]
    VM --> REG["代码 / 数据 / BSS / 堆 / 栈 / 映射区"]
    PROC --> H["文件句柄或文件描述符"]
    H --> F["磁盘上的 txt 文件"]
    RT["C / Rust / Python / JavaScript 运行方式"] --> PROC

    classDef question fill:#fff2cc,stroke:#c99a00,color:#222;
    classDef current fill:#d9ead3,stroke:#38761d,color:#222;
    classDef relation fill:#d9eaf7,stroke:#3d85c6,color:#222;
    class Q question;
    class P,L,PROC,T,VM,REG,H,F,RT current;
```

这张图表达的不是一堆孤立名词，而是一条因果链：程序保存在磁盘上；操作系统根据程序建立进程；线程在进程中执行；进程通过虚拟内存和文件接口使用机器资源；不同编程语言最终也要落到这些操作系统机制上。

## 学习状态说明

- `框架`：知道它在整个操作系统中的位置，但还没有深入学习。
- `正在学习`：问题已经出现，正在建立概念和连接。
- `已整理`：已经形成图、关系、例子、误区和自测题。
- `待复习`：内容已经整理，但还需要通过复述和练习确认真正掌握。

“已整理”不等于“已经掌握”。是否掌握，以能否脱离文档回答情境题、画出关系图并解释原因来判断。

## 首版边界

当前只详细展开了我已经提出的这一组问题：

- 程序和进程分别是什么？
- 程序怎样进入内存并开始执行？
- 代码、数据、BSS、堆和栈怎样变化？
- 打开两个 txt 文件时，文件、句柄、缓冲区和进程分别是什么？
- C、Rust、Python 和 JavaScript 在操作系统眼中怎样运行？

调度算法、线程同步、死锁、页面置换、文件系统内部结构、驱动、安全和虚拟化等主题目前只出现在总图中，不提前展开。
